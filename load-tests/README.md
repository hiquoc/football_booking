# Server Load Mock

This folder contains a k6 load-test mock for watching how CPU, memory, network, database, Redis, and Kafka usage increase on a VPS as traffic ramps up.

The default script is intentionally read-heavy. It exercises the API gateway, field search, field detail, booking availability, community listing, and optional authenticated reads without creating data. Booking writes are disabled unless `WRITE_TRAFFIC=true`.

## Install k6

On a VPS:

```bash
sudo gpg -k || true
curl -s https://dl.k6.io/key.gpg | sudo gpg --dearmor -o /usr/share/keyrings/k6-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt update
sudo apt install -y k6
```

On Windows, use:

```powershell
winget install k6.k6
```

## Run Against Local Docker

Start the app stack first:

```bash
cd backend
docker compose --profile app up -d --build
```

Then run a small smoke load from the repo root:

```bash
k6 run load-tests/server-load-smoke.js
```

## Run Against A VPS

For the clearest VPS resource numbers, run k6 from your laptop or a second VPS. If k6 runs on the same VPS as the app, `htop` and `docker stats` will include load generated by the test runner itself.

Use the gateway URL exposed by the VPS:

```bash
TARGET_URL=http://YOUR_VPS_IP:8080 TEST_PROFILE=vps k6 run load-tests/server-load-smoke.js
```

For a heavier run:

```bash
TARGET_URL=http://YOUR_VPS_IP:8080 TEST_PROFILE=stress RAMP_USERS=50 HOLD_USERS=100 PEAK_USERS=200 k6 run load-tests/server-load-smoke.js
```

If authentication should be skipped:

```bash
TARGET_URL=http://YOUR_VPS_IP:8080 AUTH_MODE=none k6 run load-tests/server-load-smoke.js
```

If your VPS has no demo data or discovery cannot find a field/sub-field, pass IDs explicitly:

```bash
TARGET_URL=http://YOUR_VPS_IP:8080 FIELD_ID=<uuid> SUB_FIELD_ID=<uuid> k6 run load-tests/server-load-smoke.js
```

## Optional Write Traffic

This creates real pending bookings and may affect availability, database size, notifications, Kafka traffic, and payment projections. Use it only on disposable test data:

```bash
TARGET_URL=http://YOUR_VPS_IP:8080 WRITE_TRAFFIC=true TEST_PROFILE=smoke k6 run load-tests/server-load-smoke.js
```

## Watch VPS Usage

In another SSH session, monitor system usage:

```bash
htop
docker stats
```

Useful service logs:

```bash
cd backend
docker compose -f docker-compose.prd.yml logs -f gateway-service user-service field-service booking-service
```

For database pressure:

```bash
docker exec -it football-prd-postgres-1 psql -U football -d booking_db -c "select count(*) from booking;"
```

## Profiles

`TEST_PROFILE=smoke` ramps to 10 virtual users for a quick check.

`TEST_PROFILE=vps` ramps to 25, holds 50, peaks at 100, then drops back down.

`TEST_PROFILE=stress` ramps harder and is meant for finding the point where response time or failure rate becomes unacceptable.

You can override profile sizes with `RAMP_USERS`, `HOLD_USERS`, and `PEAK_USERS`.
